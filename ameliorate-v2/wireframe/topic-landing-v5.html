This is a prototype of an app for integrating disputed knowledge about uncertain problems.

It’s entirely based on this ontology.md, using that as the data structure and visualizing some features that are enabled by the structure. This UX-design.md describes some of the prototype’s design in text.

Nothing here is functional. It’s hard-coded to the ontology’s “Build a wall” example, viewed as danny — new to the topic, hasn’t scored anything yet; the scores shown are alice’s, bob’s and casey’s.

v5 — changes since v4
  1. The numbers are generated now. Explore questions and Highlights come from a script that reads the ontology example (npm run generate), pasted in as a data bundle instead of hand-derived. Everything else is unchanged from v4.
  2. Guiding scores are lower. A question now only counts a path that runs along guides / clarifies edges and ends by guiding the topic, so “most effective ways” reads 0.76 (was 0.83) and “why do people immigrate” 0.48 (was 0.52).
  3. Highlights are recomputed. Disagreement is scaled by 4 rather than 8, and a scorer who left a “—” no longer counts as a 0 — so the list is ordered differently and claims (“most enter legally and overstay visas”) now reach it alongside concepts and edges.
  4. Nothing in the rendering changed: an adapter maps the bundle onto the names v4 already read, and hand-authored bits (which view a question opens, “Most active”, the criteria scores, the diagram) sit in an OVERRIDES block.
